## 2024-11-02 - Open Redirect via Control Characters Bypass

**Vulnerability:** The `getSafeRedirectUrl` function in `src/lib/auth/safe-redirect.ts` validates redirect URLs using string prefix checks (`startsWith("/")` and `startsWith("//")`) before passing them to the `URL` constructor. However, an attacker can bypass these checks by inserting control characters like tabs (`\t`), newlines (`\n`), or carriage returns (`\r`) at the beginning of the URL (e.g., `/\t/evil.com`). The JavaScript `URL` constructor automatically strips these control characters during parsing, transforming the malformed string into a protocol-relative URL (`//evil.com`) and resolving the host to `evil.com`. Because the prefix check was only performed on the raw string, it passes, but the resulting URL points to an external domain, leading to an Open Redirect vulnerability.
**Learning:** String prefix checks on raw input can be bypassed by using control characters in the URL, because the JavaScript `URL` constructor automatically strips these characters. The `URL` constructor parses the malformed string into an unintended relative path.
**Prevention:** To secure URL handling and prevent Open Redirects, always validate the post-parsed host (e.g., `parsed.hostname !== "localhost"`) rather than relying purely on pre-parse string checks. This ensures that regardless of how the URL is constructed or parsed, it will always be restricted to the expected host.
