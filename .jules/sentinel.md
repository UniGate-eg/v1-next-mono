## 2024-05-24 - Open Redirect Bypass via Control Characters
**Vulnerability:** The open redirect prevention logic (`getSafeRedirectUrl`) was vulnerable to bypass using URL control characters (e.g., `\t`, `\n`, `\r`). The initial validation correctly checked that the target path started with `/` and did not start with `//` or `/\`. However, a string like `/\t//evil.com` passes this check. When passed to the `URL` constructor with a base origin (`http://localhost`), the constructor automatically strips the control characters (`\t`), effectively parsing the malformed URL as protocol-relative (`//evil.com`), thus bypassing the validation and returning a redirect to an external site.
**Learning:** String prefix validation (e.g., `startsWith("//")`) on raw URLs is insufficient for security because URL parsers (like the JavaScript `URL` constructor or browser navigation) will often strip or normalize control characters. Relying purely on pre-parse string matching for protocol-relative URL defense is a common pitfall.
**Prevention:** Always perform security validations on the *post-parsed* URL components, rather than the raw input string. In this case, checking if the `parsed.hostname` remained strictly `"localhost"` after parsing ensures no external domain could be injected.
