## 2024-05-18 - Open Redirect via Control Characters Bypass and Path Forgery
**Vulnerability:** The URL redirect validator `getSafeRedirectUrl` checked for protocol-relative paths using `!trimmed.startsWith("//")` but this string-level check can be bypassed in two ways: 1) Using control characters like `/\t/evil.com` which are stripped by the `URL` constructor and resolve differently. 2) Using URLs with dummy hostnames that result in an unintended parsed pathname like `http://localhost//evil.com`, which returns `//evil.com`.
**Learning:** Checking string prefixes on raw inputs is insufficient for URL validation, as the `URL` constructor fundamentally transforms inputs, potentially turning a safe-looking string into an open redirect when reconstructing it from `parsed.pathname`.
**Prevention:** Always validate the *parsed* hostname (e.g. `parsed.hostname !== "localhost"`) and crucially, ensure the resulting *parsed* pathname itself does not begin with `//` or `/\\`, rather than relying solely on pre-parse string prefix checks.
