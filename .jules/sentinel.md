## 2024-03-05 - Open Redirect Bypass via Control Characters in URL Constructor
**Vulnerability:** The `URL` constructor automatically strips control characters (`\t`, `\n`, `\r`). An attacker could supply a path like `/\t/evil.com`. A simple string `.startsWith('/')` check would pass (because it literally starts with `/`), but the `URL` constructor would strip the `\t`, effectively parsing `//evil.com` as a protocol-relative URL, overriding the dummy `localhost` origin and causing an open redirect.
**Learning:** String prefix checks (e.g. `startsWith('//')`) on pre-parsed URL inputs are insufficient when using the `URL` constructor to resolve relative paths, as the constructor's sanitization of control characters can transform safe-looking strings into protocol-relative URLs.
**Prevention:** Always validate the post-parsed host (`parsed.hostname === "localhost"`) and post-parsed pathname (e.g., `!parsed.pathname.startsWith("//")`) rather than relying exclusively on string prefix checks before parsing.
