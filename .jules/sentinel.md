## 2025-02-23 - Prevent Open Redirect Bypass in safe-redirect.ts
**Vulnerability:** The `getSafeRedirectUrl` function is vulnerable to an open redirect bypass. Even though it checks if the original string starts with `//` or `/\\`, the `URL` constructor strips control characters (such as `\t`, `\n`, `\r`) during parsing. An attacker can craft a payload like `/\t/evil.com` which passes the initial string prefix checks (since it starts with `/\t`, not `//`), but when parsed by `new URL(trimmed, "http://localhost")`, the `\t` is ignored, effectively treating the URL as `//evil.com` (protocol-relative), causing `parsed.host` to become `evil.com`. Additionally, as noted, `parsed.pathname` can evaluate to malicious patterns.
**Learning:** String prefix checks on raw URLs are insufficient because the `URL` constructor cleanses malformed inputs (stripping tabs, newlines) before evaluating whether they are relative or protocol-relative.
**Prevention:** Always validate the final state of the `URL` object. Ensure `parsed.hostname === "localhost"` to guarantee the input did not act as an absolute or protocol-relative URL, and verify that `parsed.pathname` itself doesn't start with `//` or `/\\`.
