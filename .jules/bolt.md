## 2025-02-28 - MajorMatchEngine N*M String joining Bottleneck
**Learning:** Found a specific hotspot in `UniversitiesDirectoryClient.tsx` where filtering by major dynamically recalculates matches against all ~34 majors across ~200 universities during render (inside a `useMemo`). The underlying engine (`MajorMatchEngine`) was wastefully re-extracting and re-joining token arrays into corpus strings for the same university every time it was scored against a new major, resulting in massive string concatenation overhead.
**Action:** Implemented a `WeakMap<SlimSearchToken, Map<string, string>>` cache within the engine. Because the universities array is passed by reference from the `universitiesDatabase` context, we can safely use the objects themselves as cache keys, getting extremely fast lookups while automatically clearing memory when the university instances fall out of scope. This reduced synthetic worst-case execution time by ~80%.
